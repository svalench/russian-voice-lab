# Голосовая LAB

Локальный голосовой чат на русском для Mac с Apple Silicon и 16 ГБ памяти. Браузер слушает микрофон, отвечает нейросетевым голосом и останавливает ответ, когда вы начинаете говорить. Облачные API и API-ключи не нужны.

## Подготовка и запуск

Получить исходники:

```sh
git clone https://github.com/svalench/russian-voice-lab.git
cd russian-voice-lab
```

Нужны macOS на Apple Silicon, `uv` и Node.js с `npm`. Подготовка скачивает Python 3.12, зависимости, локальный Silero VAD и около 1,8 ГБ весов для **Qwen3 1.7B + ASR + Piper**:

```sh
./scripts/setup.sh
```

Запуск после подготовки не требует интернета:

```sh
./scripts/run.sh
```

Откройте **http://127.0.0.1:8765** в актуальном Chrome. Дождитесь трёх отметок готовности моделей, наденьте наушники и нажмите **«Начать разговор»**. Разрешите доступ к микрофону. По умолчанию используется русский нейроголос **Ирина / Piper**; кнопка ▷ позволяет прослушать пример без включения микрофона. Текущая LLM указана над диалогом.

### Меньшая модель и сравнение

Основной профиль теперь **Qwen3 1.7B 4-bit** без режима рассуждений: ответы сразу передаются на озвучивание. Прежняя 4B-модель сохранена в отдельном каталоге. Для сравнения меняется только LLM, а распознавание и голос остаются теми же:

```sh
# Основной режим:
./scripts/run.sh
# Прежняя LLM 4B, тот же русский голос:
VOICE_LAB_LLM=4b ./scripts/run.sh
```

Остановите предыдущий сервер перед переключением. Для загрузки 4B на новом компьютере: `VOICE_LAB_LLM=4b ./scripts/setup.sh`. Весам 1.7B соответствует `.models/llm-small/`, прежним 4B — `.models/llm/`; переключение их не перезаписывает. При обновлении уже установленного приложения достаточно загрузить новую LLM: `.venv/bin/python scripts/prepare.py models --llm small --only-llm`. [Сравнение скорости и качества](MODEL_COMPARISON.md): меньшая модель быстрее, но допускала ошибки в счёте и формулировках.

Qwen3-TTS / Ryan сохранён как сравнительный синтезатор: `VOICE_LAB_TTS=qwen ./scripts/run.sh`. При необходимости его подготовки выполните `./scripts/setup.sh --qwen-voice`; для основного режима затем снова `./scripts/setup.sh`, чтобы установить зависимости Piper. Qwen3-TTS на этом M4 оказался медленнее воспроизведения. Список голосов соответствует выбранному синтезатору. Итоги первоначальных измерений — [VALIDATION.md](VALIDATION.md).

Говорите по-русски. После 700 мс тишины начинается обработка. Пауза регулируется от 400 до 1600 мс. Чтобы перебить ответ, начните говорить. «Остановить» выключает микрофон и отменяет ответ; «Новый разговор» очищает контекст. Голос и инструкцию собеседнику можно менять между сессиями.

## Что работает локально

| Этап | Модель / библиотека |
| --- | --- |
| Детекция речи | Silero VAD v5 / ONNX Runtime WASM / AudioWorklet |
| Распознавание | `mlx-community/Qwen3-ASR-0.6B-4bit` |
| Ответ по умолчанию | `mlx-community/Qwen3-1.7B-4bit`, `enable_thinking=False` |
| Сравнительная LLM | `mlx-community/Qwen3-4B-Instruct-2507-4bit` |
| Синтез по умолчанию | Piper / `ru_RU-irina-medium` (ONNX, CPU) |
| Сравнительный синтез | `mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-4bit` |

ASR, LLM и Qwen3-TTS исполняются через MLX на GPU Apple; Piper использует CPU. Это последовательный разговорный конвейер с перебиванием; модель не рассуждает одновременно с произнесением вашей реплики. PersonaPlex исключён из-за заявленной поддержки английского языка. Системный голос macOS и Web Speech API не используются.

Тяжёлые операции выполняет один поток: ASR → фраза LLM → поток TTS → следующая фраза. Это ограничивает пиковую память и исключает одновременную запись в состояние MLX. Очередь выходных событий ограничена, заменённая ожидающая задача отменяется. Входная реплика ограничена минутой, ответ — 256 текстовыми токенами, контекст вместе с резервом ответа — 4096 токенами. Кэш LLM повторно использует совпадающий префикс; при заполнении контекста старые реплики удаляются блоком, освобождая около половины окна. Текстовая сессия ограничена 256 репликами пользователя; уже воспроизведённое аудио на сервере освобождается.

Браузер немедленно останавливает звук при детекции новой речи. Сервер отменяет генераторы при ближайшем токене или аудиофрагменте, помечает реплики идентификаторами и отбрасывает устаревшее аудио. История использует подтверждения фактического воспроизведения. Для прерванной посреди фразы речи озвученная часть повторно распознаётся локальным ASR перед следующим ответом; это может добавить задержку, а её текст зависит от точности распознавания. Фрагмент короче 100 мс в контекст не включается.

## Данные, сеть и диск

- Сервер слушает только `127.0.0.1:8765`, обслуживает одну активную вкладку и проверяет Origin WebSocket.
- Библиотеки, WASM и VAD загружаются с этого же сервера. CDN, телеметрия Hugging Face и онлайн-загрузка моделей при запуске отключены.
- Телеметрия Python ONNX Runtime отключена до создания Piper-сессии. Код Piper распространяется по GPLv3; исходная карточка голоса сохраняется в `.models/piper/ru/ru_RU/irina/medium/MODEL_CARD`.
- Аудио и история находятся в памяти, запись микрофона на диск не ведётся. Экспорт вручную скачивает JSON с текстом и метриками. Новое подключение к WebSocket начинает новую серверную сессию.
- При переподключении прежний текст остаётся на экране и в экспорте; контекст нового разговора начинается заново. Модели и вычислительные кэши остаются в памяти до остановки сервера.
- `.models/` содержит веса и manifest с ревизиями; `.cache/` — кэши и диагностические результаты; `.venv/` — окружение. Эти каталоги и `web/assets/` исключены из Git.
- Подготовка сохраняет минимум 5 ГБ свободного места. Если места недостаточно, обычный запуск остановится с объяснением. Разрешённую очистку старых кэшей Xcode можно включить командой `./scripts/setup.sh --clean-build-cache`: удаляются только каталоги сборок DerivedData и только если не обнаружена активная сборка. Личные файлы, Downloads, корзина и проекты не удаляются.

## Задержки и проверка

«Первый звук» измеряется браузером от последнего речевого кадра до запланированного начала первого аудиофрагмента, включая ожидание паузы VAD. Точное акустическое время включает аппаратную задержку устройства. ASR и первый токен измеряются сервером. «Синтез / аудио» — время генерации, делённое на длительность аудио: **меньше 1 — быстрее воспроизведения**. Фактические метрики зависят от прогрева, других приложений и нагрева MacBook Air.

Серверные тесты без загрузки моделей:

```sh
.venv/bin/python -m pytest -q
```

Проверка настоящих моделей с заблокированными исходящими Python-соединениями:

```sh
.venv/bin/python scripts/benchmark.py --llm small --turns 10 --output .cache/benchmark-small.json
.venv/bin/python scripts/benchmark.py --llm 4b --turns 10 --output .cache/benchmark-4b.json
# Дополнительная проверка непрерывной работы:
.venv/bin/python scripts/benchmark.py --llm small --turns 10 --minutes 10 --output .cache/benchmark-small-soak.json
```

Диагностика генерирует русские входные реплики через TTS и прогоняет полный конвейер. Отчёт — `.cache/benchmark.json`. Это синтетическая проверка совместимости, памяти и задержек; она не измеряет независимую точность ASR на человеческой речи, естественность голоса, эхоподавление или акустическую задержку микрофона.

Браузерная проверка использует отдельный явно тестовый backend (без подмены моделей в основном приложении). Для неё нужен Playwright с Chromium/Chrome:

```sh
python3 tests/ui_server.py
# В другом терминале:
python3 tests/browser_check.py
```

Она проверяет реальные локальные WASM/VAD/AudioWorklet, включение и остановку искусственного микрофона, отказ в доступе, экспорт, мобильную вёрстку и отсутствие внешних запросов. Скриншоты и отчёт сохраняются в `test-results/`.

После создания синтетического WAV командой `benchmark.py --tts piper` полный браузерный тест с настоящими моделями выполняется командой `python3 tests/browser_models.py` при запущенном основном сервере. Он подаёт нейросетевую речь в AudioWorklet вместо живого микрофона, проверяет транскрипцию, ответ и перебивание.

Длительный тест реального сервера: `.venv/bin/python tests/session_soak.py --minutes 10 --turns 10` (сервер запущен в режиме Piper). Он использует нейросетевые входные реплики и имитирует подтверждения воспроизведения; физический звук и микрофон не измеряет.

Для окончательной оценки поговорите 10 минут в наушниках, проверьте перебивания, имена, числа и паузы внутри фраз. Затем повторите на динамиках. Цели после прогрева: медиана первого звука до 3 с, остановка при перебивании до 300 мс, синтез с коэффициентом ниже 1. Эти значения не гарантируются моделью или железом.

## Устранение проблем

- **Нет модели / локальных ресурсов:** повторите `./scripts/setup.sh`; загрузки возобновляются. Для полной повторной загрузки конкретной модели удалите только её каталог в `.models/`.
- **Микрофон запрещён:** разрешите доступ к микрофону для `127.0.0.1` в браузере и macOS → Конфиденциальность и безопасность → Микрофон, затем снова нажмите «Начать разговор».
- **Собеседник перебивает себя:** используйте наушники; браузерное эхоподавление включено, но зависит от устройства и помещения.
- **Большая задержка:** закройте тяжёлые приложения, дождитесь прогрева, используйте короткие ответы и проверьте метрики ASR/LLM/TTS. Увеличение паузы VAD прямо увеличивает время ожидания ответа.
- **Qwen3-TTS говорит с паузами:** переключитесь на профиль Piper выше. При включённом энергосбережении Mac замеры могут быть медленнее; настройки питания приложение не меняет.
- **Соединение потеряно:** проверьте терминал, перезапустите сервер и начните новую сессию. После закрытия вкладки разговор прерывается; новый сеанс начинается с чистой историей.
- **Порт занят:** остановите предыдущий запуск в его терминале сочетанием Ctrl+C. Номер порта задаётся в `scripts/run.sh`.

## Локальный протокол

`GET /api/status` сообщает готовность моделей, доступные голоса, память, место и занятость сессии. `WS /api/session` принимает `configure`, `speech_start`, `speech_end`, `speech_misfire`, `stop`, `reset`, `preview`, `playback`, а также бинарный mono PCM Float32 little-endian 16 кГц (до 8192 байт на сообщение).

Сервер отдаёт состояния, транскрипцию, текстовые приращения, границы фраз, метрики и ошибки. Каждый `audio` JSON-заголовок содержит `turn_id`, `phrase_id`, `chunk_id`, `sample_rate`; за ним следует бинарный PCM Float32. Браузер подтверждает число воспроизведённых сэмплов по `chunk_id`. Этот протокол внутренний, публичный сетевой API не предоставляется.
